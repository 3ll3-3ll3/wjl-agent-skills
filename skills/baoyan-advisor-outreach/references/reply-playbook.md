# 导师回信处理手册

# 总原则

先读取完整回信和线程，再判断老师真正表达的含义。不要只根据一句预览推断。

除非用户明确说“发送”“帮我回”“直接回复”，否则只起草，不自动发送。

# 分类与动作

## `positive_master`

典型表述：

- “欢迎填报我名下的硕士招生指标”；
- “可以报我”；
- “后面可以详细交流”；
- “欢迎加入/欢迎申请”。

处理：

1. 提取老师给出的实验室、课题组、网站、联系方式和下一步动作；
2. 重新调研团队近期研究、学生去向、培养方式和用户最适合的切入课题；
3. 起草感谢回信；
4. 如果用户决定填报该导师，可在回信中明确已填报；
5. 若用户明确“有科大录取一定去”，可以表达坚定意愿，但不要写不真实承诺。

## `quota_unknown`

典型表述：

- “目前指标未知”；
- “等面试之后再联系”；
- “后续再说”。

处理：

- 简短致谢即可；
- 数据表标记为后续跟进；
- 记录触发条件，例如“通过科学岛面试后再次联系”；
- 不频繁追问指标。

## `phd_only`

典型表述：

- “只有直博名额”；
- “是否考虑读博？”

用户当前只考虑硕士，因此默认起草礼貌婉拒：感谢认可，说明当前规划仍是先读硕士，现阶段不考虑直博；如果后续有硕士名额，希望继续请教。

不能替用户接受直博。

## `no_quota`

典型表述：

- “没有名额”；
- “今年不招生”；
- “已满”。

处理：简短感谢，不纠缠；如老师主动推荐其他导师，再进入 `redirect`。

## `redirect`

记录老师推荐的导师、实验室或项目，先做去重：已联系过则不重复发；未联系过再进入候选核验流程。

## `needs_followup`

包括：

- 约电话/视频交流；
- 让补发简历、成绩单、排名证明；
- 让阅读论文或准备具体方向；
- 让参加考核。

处理：把具体任务、时间、材料和问题拆出来，优先帮助用户准备，不擅自确认时间或提交材料。
