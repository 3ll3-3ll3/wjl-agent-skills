# 目标

把“找导师 → 核验 → 排序 → 个性化写信 → 人工确认 → 单独发送 → 记录 → 处理回信”的完整流程固化为可复用 Skill。

本 Skill 当前主要服务 2027 届推免，尤其是中国科学技术大学研究生院科学岛分院 `085400 电子信息`，但同样可扩展到其他学校、学院和专业。

# 触发条件

当用户出现以下意图时启用：

- “再找一些导师/候选”；
- “这个老师适合我吗”；
- “给这些老师写套磁邮件”；
- “逐个发/全部发”；
- “查一下有没有回信”；
- “帮我回老师”；
- “哪些老师已经发过，不要重复”；
- “继续按之前流程做”。

# 数据真源

执行前读取：

1. `data/science-island-2027-outreach.yaml`：已经发送过的导师、批次和已知回信状态；
2. `references/email-writing-rules.md`：邮件固定规则；
3. `references/reply-playbook.md`：回信处理规则。

历史表只保存用于去重和工作流恢复的结构化状态，不保存 Outlook message id、完整邮件正文、用户邮箱密码、令牌、浏览器会话或附件原件。

如果邮箱中的实时状态与仓库快照冲突，以邮箱实时结果和用户最新说明为准，并在用户明确要求更新仓库时同步修订数据文件。

## 个人材料与附件真源

个人简历、正式成绩单及后续套磁邮件实际使用的附件，默认以用户连接的 Microsoft Outlook 邮箱中的最新有效版本为真源，不再默认依赖当前聊天上传文件、项目目录中的旧文件或 Skill 内硬编码的个人信息。

当前已在 Outlook 中确认可用的附件命名包括：

- `王家乐个人简历r2.pdf`；
- `成绩单.pdf`。

这些文件名只作为当前线索，不视为永久固定名。以后若邮箱中出现更新时间更晚、明显属于新版的简历或正式成绩单，应优先使用新版。

在需要从个人材料提取 GPA、专业排名、课程成绩、奖项、项目经历或联系方式时，应优先从最新简历和正式成绩单重新核验，不得继续沿用 Skill 中的旧数值。尤其不得把历史记录中的专业排名 `2/40` 等旧信息当成当前事实。

# Outlook 附件获取流程

当用户要求建立草稿、发送套磁邮件，或需要核验最新简历内容时，按以下流程从 Outlook 获取附件：

1. 在 Outlook 中搜索近期由用户本人发出的、带附件的推免/套磁邮件，优先使用与当前申请阶段相近的邮件；
2. 对候选邮件调用附件列表，确认同时存在“个人简历”和“成绩单”两类 PDF；
3. 简历文件名优先匹配“王家乐”“个人简历”“简历”等关键词，成绩单优先匹配“成绩单”“正式成绩单”等关键词；
4. 如有多个版本，优先选择最近发送或最近修改、且明显为新版的版本；
5. 使用邮箱附件获取能力分别取得这两个附件的文件引用；
6. 创建草稿或发送邮件时，直接使用从 Outlook 获取到的附件文件引用，不从 GitHub 仓库读取附件原件；
7. 不把 Outlook message id、attachment id、临时下载链接、文件引用、邮箱密码或令牌写入 GitHub；
8. 如果存在多个版本且无法判断哪个是最新版，先向用户确认，不自行猜测；
9. 如果 Outlook 连接不可用，应明确说明并要求恢复邮箱连接。除非用户明确授权，不自动退回使用聊天上传的旧附件。

完成一次附件取用后，可以在当前执行上下文中复用已经取得的文件引用，避免对同一附件重复下载；跨会话则重新从邮箱核验。

# 候选导师筛选

## 第一优先方向

优先寻找：

- 人工智能、机器学习、深度学习；
- 计算机视觉、医学图像、遥感智能分析；
- 多模态、多源信息融合、智能感知；
- 大数据、数据挖掘、知识工程、智能决策；
- 自动驾驶感知、机器人视觉、状态估计、轨迹预测；
- 与概率统计、高维数据、优化、数学建模联系紧密的交叉方向。

## 次优先方向

可作为补充：

- 机器人控制、人机交互、智能系统；
- 智慧健康、健康数据、风险预测；
- 农业智能、环境数据、光谱数据分析；
- 传感与检测中明显偏算法、数据或模式识别的课题。

## 不优先方向

除非用户主动要求扩大覆盖面，否则不优先：

- 纯机械设计；
- 纯硬件、芯片、材料与器件；
- 传统控制但缺少智能算法成分；
- 电机、嵌入式等工程实现为主的方向；
- 纯数值计算。数值计算可以作为本科经历，但不是用户首选研究方向。

# 候选导师核验

每位导师至少核验以下事项：

1. 当前是否仍在官方导师/人员名单；
2. 最近 1–3 年实际研究方向，而不是只看旧主页标签；
3. 是否存在 `085400 电子信息`、推免硕士或跨专业招生证据；
4. 是否允许数学、统计、计算机之外背景切入；
5. 近期论文、项目或团队页面是否能证明 AI/数据/算法成分；
6. 当前公开工作邮箱是否可靠；
7. 是否属于资历过老、兼职、退休边缘、招生资格存疑等需要特别提示的情况。

涉及当前招生资格、导师状态、截止时间、招生专业等动态事实时，必须优先查官方网页并注明不确定性。

# 排序逻辑

默认使用以下思路综合排序，不输出伪精确分数：

`方向匹配 + 数学背景友好 + 085400可招生 + 捡漏概率 + 就业通用性 + 导师明确意愿`

现实回信权重大：已经明确表示欢迎填报名额、愿意进一步交流的导师，应显著提高后续跟进优先级。

# 去重规则

在起草或发送前，必须先检查 `data/science-island-2027-outreach.yaml`。

- `status` 已为 `sent_*`、`reply_*` 或 `closed_*` 的导师，默认不得重新发送首封套磁邮件；
- 姓名相同但邮箱不同，应先核验是否同一人；
- 用户明确要求“补发/重发”时才可绕过去重；
- 最终发送前若邮箱连接可用，再搜索历史主题或收件人做第二次去重。

# 邮件起草

正文采用“约 80% 固定 + 20% 针对导师方向定制”。

固定主线：

- 苏州大学数学科学学院数学与应用数学本科；
- GPA、专业排名、课程成绩等个人数值信息必须从 Outlook 中最新简历和正式成绩单核验后再写，不硬编码；
- 数学与统计基础扎实；
- 全国大学生数学竞赛数学 A 类省一等奖；
- 全国大学生数学建模竞赛省一等奖；
- 研究兴趣优先 AI、机器学习、大数据、CV、智能感知等；
- 明确询问当前目标项目的推免硕士名额、数学背景是否适合、能否进一步交流或参加考核。

项目经历只允许概括为一句：

> 本科期间也参加过国家级大学生创新项目和数学建模竞赛，对数据分析、机器学习和数学建模有一定接触。

不得把 LBM、Black-Scholes、Chapman–Enskog、NIPT、K-means++、遗传算法等具体项目细节作为套磁邮件主叙事，除非用户针对某位导师明确要求展开。

完整写作规则见 `references/email-writing-rules.md`。

# 发送规则

邮件发送属于外部写操作，必须有用户当前明确授权，例如“发送”“逐个发”“这几封都发”。仅要求“写给我看”时不得发送。

获得授权后：

1. 每位导师单独发一封；
2. 不使用群发；
3. 默认无 CC、无 BCC；
4. 主题使用统一模板；
5. 正文使用该导师对应个性化版本；
6. 默认附个人简历和正式成绩单；这两个附件必须按“Outlook 附件获取流程”从邮箱实时取得；
7. 在发送前再次确认正文中的 GPA、排名、课程成绩等与当前最新附件一致；
8. 发送成功后，把导师状态视为已联系，后续不得重复发首封；
9. 工具无即时错误只表示提交发送成功，不等于邮箱地址一定有效；若出现退信，重新核验邮箱再决定是否补发。

# 回信处理

收到导师回信后先读取完整线程，再归类：

- `positive_master`：明确欢迎报考、欢迎填指标、愿意交流；
- `quota_unknown`：指标未定、让通过面试后再联系；
- `phd_only`：只有直博指标；
- `no_quota`：明确无硕士指标；
- `redirect`：建议联系其他导师或其他项目；
- `needs_followup`：需要补材料、约时间、进一步沟通；
- `other`：无法直接归类。

按 `references/reply-playbook.md` 处理。未经用户明确授权，不自动发送回复。

# 用户当前长期偏好

- 只优先考虑硕士，拒绝直博；
- 研究方向优先 AI、机器学习、大数据、CV、智能感知和数据驱动交叉；
- 数学本科背景是优势，要强调理论基础和学习能力；
- 代码与工程能力相对弱，不虚构熟练程度；
- 不把纯数值计算包装为核心兴趣；
- 就业导向明显，优先通用 AI/算法/数据方向；
- 不再主动关注国家电网体系项目。

# 异常与边界

- 官方信息和第三方信息冲突时，以最新官方信息优先；
- 当前导师邮箱不确定时，不猜邮箱；标记待核验；
- 老师已退休、兼职或招生资格存疑时，必须在发送前明确提示；
- 不虚构导师项目、论文、招生名额、回信内容或已发送状态；
- 不把历史研究方向当成当前方向，必须注明时间；
- 不因“捡漏”目标而发送明显不匹配的导师；
- 不上传成绩单、简历等原始附件到公开 GitHub 仓库；
- 不把 Outlook message id、attachment id、临时下载链接或邮箱内部文件引用写入仓库；
- Outlook 中个人材料与当前聊天中的旧版本冲突时，默认以 Outlook 最新有效附件为准，除非用户明确指定其他版本。

# 最终验收

一次完整执行应满足：

- 已排除历史已发导师；
- 每位新增候选都完成当前身份和方向核验；
- 给出与数学背景的具体衔接点；
- 邮件没有夸大代码能力或项目经历；
- 正文中的 GPA、排名、课程成绩等已从 Outlook 最新简历/成绩单核验；
- 草稿或发送所附简历、成绩单来自 Outlook 最新有效附件；
- 发送前用户已明确授权；
- 发送为逐封单独发送；
- 回信被准确分类并保留后续行动建议；
- 若用户要求持久化，更新结构化历史表而不是保存完整私人邮箱内容或附件原件。
