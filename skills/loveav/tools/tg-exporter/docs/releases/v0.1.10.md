# TG Exporter v0.1.10

这是一个针对 **Windows 打包版 `tgctl.exe` 输出/退出码契约** 的小型 hotfix。GUI、Telegram 读取/搜索、真实 forward/send、导出目录和 Session 模型均不改变。

## 修复

- 修复部分非 UTF-8 Windows 控制台/重定向环境中，`tgctl.exe` 输出中文 JSON 错误信息时可能触发 `UnicodeEncodeError` 的问题。
- 该二次异常会让原本已经正确识别的 `SESSION_BUSY` 无法正常输出，并把预期退出码 `8` 变成 PyInstaller 顶层退出码 `1`。
- `tgctl` 现在启动时明确将 stdout/stderr 配置为 UTF-8；JSON stdout 保持严格 UTF-8，普通诊断 stderr 使用安全错误处理，避免错误处理本身再次崩溃。
- `SESSION_BUSY` 的正式契约恢复为：结构化 JSON `error.code=SESSION_BUSY` + native process exit code `8`。

## 回归保护

Windows CI 不再只测试 Python 函数返回值，而会：

1. 构建真实 one-file `tgctl.exe`；
2. 用独立进程持有真实 OS `SessionLease`；
3. 在隔离的临时 AppData 中启动打包版 `tgctl.exe status --json`；
4. 捕获 native stdout/stderr/ExitCode；
5. 强制验证 JSON 为 `SESSION_BUSY` 且进程退出码严格等于 `8`。

这样可覆盖源码测试无法发现的 Windows/PyInstaller 控制台编码差异。

## v0.1.9 真人 E2E 结论

本 hotfix 来源于 v0.1.9 的真实 Windows 验收。已确认可用的核心能力包括：

- 旧 Session 直接复用；
- GUI 启动和小范围真实导出；
- `status`、聊天列表/搜索、Telegram Chat Folder；
- 消息 search/get；
- `MESSAGE_NOT_FOUND`、`AMBIGUOUS_CHAT`；
- forward/send dry-run；
- 真实 forward/send 到 Saved Messages；
- 20 条默认 forward 闸门和 200 条硬上限；
- 日志不泄露测试正文/API hash/手机号/OTP/2FA。

仍不建议为了测试故意触发真实 FloodWait。迁移群具体映射、Saved Messages 最终视觉表现以及 tgctl→GUI 反向锁仍可继续做人工补充确认，但不构成本 hotfix 的代码范围。
