# TG Exporter v0.3.0

第三代正式版本：在第二代 single-daemon / Windows Named Pipe IPC 基础上加入 **Personal Account Reader**，同时保留既有 GUI 导出和 `tgctl` 写操作安全边界。

## 主要变化

```text
TGExporter GUI ─┐
               ├→ TG daemon → Telegram user Session
tgctl / Codex ─┘
```

- daemon 是唯一 Telegram Session / Telethon owner；
- 同代 GUI 与 `tgctl` 可以同时使用，不再各自 direct-open SQLiteSession；
- legacy/direct 进程占用 Session 时继续返回结构化 `SESSION_BUSY`，Windows packaged native exit code 保持 8；
- export 活跃时 reader 等待；真实 `send/forward` 立即 `EXPORT_IN_PROGRESS`，不会排队后偷偷执行；
- GUI 关闭或崩溃后 daemon-side export job 可继续；
- phone / OTP / 2FA 仍只由 GUI 处理。

## Personal Account Reader

新增/扩展：

```text
tgctl account get
tgctl dialogs list
tgctl chats get
tgctl chats members
tgctl messages history
tgctl messages search
tgctl messages get
tgctl topics list
tgctl topics history
tgctl media download
```

Reader 能力包括：

- group / supergroup / channel / private / bot / Saved Messages / archive / forum / Telegram Folder；
- default page 100、max 500；HMAC/query-bound opaque cursor；
- Rich MessageInfoV3：structured sender、reply、forward、entities、reactions、poll、service action、media metadata 等；
- Basic Group → Supergroup logical history current → legacy，唯一定位键 `(source_chat_id, message_id)`；
- owner/admin/member 为查询时 current snapshot；anonymous admin / send-as 不反推隐藏个人；
- advanced search：single/global、sender、role、时间、消息类型、topic、链接、真实 URL hostname；
- Forum topic list/history；
- JSON / bounded JSONL；
- 普通 reader 默认 media metadata-only。

## Current-unread correctness fix

v0.3.0 修复 Issue #22：每个使用 **current unread** 的群，在该群真正开始执行导出的时刻单独冻结边界：

```text
lower = read_inbox_max_id_at_group_start
upper = latest_message_id_at_group_start
export only lower < message_id <= upper
```

因此：

- 不再使用 catalogue refresh 时可能已经过期的 unread snapshot；
- multi-group batch 中每个群都有自己的 export-start snapshot；
- snapshot 之后才到达的新消息不进入本轮；
- optional read-ack 只使用同一个 frozen upper bound；
- export failure 不 read-ack；
- JSON success + read-ack failure 时 JSON 仍保留；
- Basic Group → Supergroup 的 current-unread 只使用当前 logical Supergroup，不使用 legacy Basic Group。

## Media download safety

显式媒体下载仍不是默认 Reader 行为，而是两阶段本地磁盘操作：

```text
plan → confirmation token → download
```

- 第一次只生成计划，不下载；
- normal：最多 20 files / 500 MiB；
- 显式 large：最多 200 files / 5 GiB；
- `.part` 成功后 atomic rename；
- path/basename 做 Windows 安全化；
- 已确认 write/download transport outcome 不自动 retry。

## Compatibility / write safety

旧命令继续兼容：

```text
status
chats list
messages search
messages get
forward
send
```

安全边界保持：

- `forward` 使用真实 Telegram forward，不静默复制正文；
- `send` 只发送纯文本；
- `forward/send` 保留 `--dry-run`；
- forward 默认 20，显式 large 后 hard cap 200；
- 同名目标返回 `AMBIGUOUS_CHAT`，不 first-match；
- FloodWait 结构化返回，不 retry storm；
- write outcome 不确定时返回 `WRITE_OUTCOME_UNKNOWN`，不自动重放；
- 普通日志不记录 credentials、Session、access_hash/file_reference、message body/caption/URL text/media filename。
