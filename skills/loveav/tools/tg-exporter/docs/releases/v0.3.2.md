# TG Exporter v0.3.2

Status: **release authorized**.

Base Production: `v0.3.1` / `38b5687038f5ac458571a65820744a7bd325564f`.
Development PR: `#26` / `codex/v0.3.2-sender-role-fix`.

## Scope

v0.3.2 is a narrow patch release for sender identification and `tgctl messages search --sender-role` filtering. It is not a reader redesign, does not add LoveAV/PikPak business classification, and does not change the ordinary GUI export format, directories, current-unread semantics, Session ownership, IPC, daemon lifecycle, or media behavior.

## Sender-role recovery improvements

When Telegram provides structured sender evidence but the sender entity is not already hydrated, a search that explicitly uses `--sender-role` may perform one bounded recovery through the existing Telegram client. Resolution is cached per request, including failed lookups, so the same peer is not fetched once per message.

`--sender-role admin` can match, when Telegram provides sufficient structured evidence:

- a current administrator;
- the current owner;
- a Telegram-explicit anonymous administrator;
- a message explicitly posted as the current group/chat.

It does not match:

- ordinary members;
- an administrator that appears only in `forward_origin`;
- a row with only textual `post_author` and no sender peer evidence;
- a fully unidentified `unknown` message.

Telegram-explicit anonymous administrators remain anonymous: no individual user id is guessed. Current-chat send-as records the chat identity and may be treated as an administrator source without guessing which individual administrator posted it.

## Performance boundary

The patch's additional sender resolver is enabled only for searches that use `--sender-role`.

Ordinary GUI/manual export, ordinary history, and searches without `--sender-role` do not enable the additional sender entity recovery introduced by this patch. The existing read-only and bounded-reader defaults remain unchanged.

## Release build policy

The formal v0.3.2 binaries are rebuilt from the merged `main`; Candidate binaries are not relabeled as Production. The Release workflow refuses to overwrite an existing historical tag or Release and publishes:

```text
TGExporter-v0.3.2-windows-x64.exe
TGExporter-v0.3.2-windows-x64-portable.zip
tgctl.exe
SHA256SUMS.txt
```

Formal Release hashes are the values in the published `SHA256SUMS.txt`.

## Safety boundaries unchanged

This release does not expand Telegram write permissions. Reader defaults remain read-only. No new real send/forward/read-ack/media-download/group-mutation/Session-reset permission is introduced by this patch.

The existing `v0.3.1` tag/Release must not be moved, overwritten, deleted or rebuilt in place.
