# TG Exporter v0.1.8

本版改变本地输出组织方式，并修复普通群升级超级群后在选择器中出现重复项的问题。

## 导出分类

- 新增软件内 `管理分类`。
- 导出分类是 TG Exporter 的本地概念，与 Telegram Chat Folder 分离。
- 自定义分类和每群分类分配保存在本机 `settings.json`。
- 内置 `未分类` 作为默认兜底。
- 新建分类后会在当前总输出目录下自动创建对应一级文件夹。
- 更换总输出目录后，分类文件夹会在新根目录自动建立。
- 软件内删除分类不会删除磁盘上的历史目录或 JSON。
- 分类名做 Windows 路径安全校验，避免非法字符和保留设备名。

## 新输出结构

旧结构：

```text
总输出目录 / 本次批次时间 / 群组 / result.json
```

v0.1.8 起：

```text
总输出目录 / 分类 / 群组 / YYYY-MM-DD_HH-mm-ss.json
```

示例：

```text
D:\TG导出\
├─ 第一类\
│  ├─ 群组1\2026-08-29_18-55-01.json
│  └─ 群组2\2026-08-29_18-55-01.json
└─ 第二类\
   ├─ 群组3\2026-08-29_18-55-01.json
   ├─ 群组4\2026-08-29_18-55-01.json
   └─ 群组5\2026-08-29_18-55-01.json
```

同一个群如果在同一秒再次导出，会自动生成 `_2`、`_3` 等后缀，不覆盖旧文件。

聊天 JSON 现在使用 `.tmp -> replace` 原子写入，避免中断时留下半写文件。

## Basic Group -> Supergroup 去重

Telegram 在普通群升级为超级群后，会保留迁移前 legacy Basic Group peer。v0.1.7 及更早版本可能把旧 peer 和当前 Supergroup 同时展示，造成看起来“同一个群出现两遍”。

v0.1.8：

- 识别 Telegram 显式 `migrated_to` 关系；
- 选择器只显示当前 Supergroup；
- 不按群名做猜测式去重，避免误合并两个真实同名群；
- 不删除、退出、修改或降级任何 Telegram 群；
- legacy peer id 仅作为内部历史来源保留；
- 旧工作群选择、标已读偏好、导出分类等 UI 配置会尽量迁到当前 Supergroup；
- 不把旧 peer 的 since-last checkpoint 直接复制到新 peer。

## 跨迁移历史

对于检测到 `migrated_from_chat_id` 的群：

- `当前未读`：只读当前 Supergroup；
- `上次导出以后`：只读当前 Supergroup；
- `指定时间范围`：读取 legacy Basic Group + current Supergroup，再按时间合并到一个本次 JSON。

当前保留旧/新 peer 的原始 message id，不在没有 Telegram Desktop 对照依据时擅自重编号。

## 保持不变

- 聊天消息仍只导出 text/caption；不下载照片、视频、文件、语音、贴纸。
- Telegram Chat Folder 仍然只读，只用于选择群组。
- 群头像仍然只作选择器 UI 元数据。
- `导出后标已读` 仍默认关闭，并严格执行 JSON 成功 -> checkpoint -> optional read ack。
- AppData 兼容路径仍为 `%APPDATA%\TelegramMultiChatExporter\`，升级不要求重新登录。

发布前必须通过：

- `pytest -q`
- GUI import check
- Windows one-file PyInstaller build + packaged smoke-test
- Release one-file + portable build
- 两种 packaged smoke-test
- SHA256SUMS
- GitHub Release assets upload

真实账号发布后重点验证：分类创建/持久化、实际输出目录、原先重复的 migrated 群是否只剩一个当前 Supergroup、跨迁移日期历史是否完整。
