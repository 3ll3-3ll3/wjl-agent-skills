# v0.1.3 qasync modal-dialog fix

A real-account login test on Windows confirmed that Telegram transport and the Windows/Clash proxy were working, but the first-login GUI could trigger qasync task re-entry while a modal Qt dialog was running.

Observed sequence:

- Windows proxy detected at `http://127.0.0.1:7890`.
- Telegram transport connected successfully.
- Account was not yet authorized (normal for first login).
- A blocking Qt input dialog started a nested Qt event loop while Telethon background send/receive tasks were active.
- qasync raised `RuntimeError: Cannot enter into task ... while another task ... is being executed`.

v0.1.3 replaces blocking dialogs inside async flows with non-blocking dialogs whose `finished` signals are awaited by asyncio. No change is required to the user's Telegram API credentials or Clash configuration.
