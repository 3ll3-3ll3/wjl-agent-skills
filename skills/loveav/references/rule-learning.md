# 自适应规则学习

LoveAV 的规则不是一次写死的黑名单。现有规则是可回归的基线，用来稳定处理已知格式；遇到新格式时，Skill 必须先审查证据，再决定是否把它纳入规则。

## 每次输入的判定层

1. **基线接受**：符合当前工具规则，来源上下文和字段证据一致。
2. **明确排除**：确认是日期、栏目、广告、导航、跟踪参数、说明文字或其他噪声。
3. **待复核 `review`**：形状新、上下文矛盾、来源不完整、链接和文本冲突，或只有很弱的单一证据。

未知格式不能仅凭“看起来不像旧格式”直接丢弃。对于可疑项，检查原始片段（仅保留在当前预览）、附近标签/标题、URL 主机和路径、同一输入中的重复关系、跨文件出现情况，以及是否命中已知噪声。链接检测、番号检测和来源检测必须分别给出证据。

## 建议记录

如宿主支持本地写入，待复核和已确认的建议放在私有资料目录：

```csv
tool,suggestion_id,pattern,match_type,decision,scope,evidence,positive_examples,negative_examples,status,created_at,promoted_rule_version
missav,rl-0001,030515-821,code_shape,accept,answer_text,source label and detail path,030515-821,030515-821号,review,2026-08-27T00:00:00Z,
```

`status` 使用 `review`、`accepted`、`rejected`、`promoted`。建议记录不是精选历史，也不是黑名单；不能因为同一候选再次出现就自动升级。

## 晋级条件

- 用户明确确认“接受/加入规则”，而不是只确认某一条结果；
- 至少有一个应命中的正例和一个不应命中的负例；
- 规则作用域明确（工具、字段、来源类型或 URL 主机）；
- 已运行回归检查，旧样本的误报和漏检没有恶化；
- 生成新的规则版本和变更说明，保留旧版本可回滚。

如果用户只确认某个结果，最多把该结果加入精选库，不得宣称学会了通用规则。拒绝的例子也要保留为防误报样本，但不要生成永久黑名单，除非用户明确要求。

## 回复格式

每次包含可疑项时，分开报告：已接受、明确排除、待复核、错误。待复核项必须列出候选值、来源位置、支持证据、反对证据和需要用户回答的最小问题；不得混入“可直接复制”的正式列表。
