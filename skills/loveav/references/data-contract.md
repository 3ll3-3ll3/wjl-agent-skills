# 本地数据契约

## 长期保留边界

LoveAV 长期重要数据以两类为准：

- Whos.tv 已解决答案的既有 Markdown、截止点状态和必要备份；
- 用户明确选择入库的 MissAV 精华数据，以及每批最终 Raindrop 导入 CSV。

规则文件维持现状；普通处理记录、临时预览、Telegram 原文和每次运行流水不属于必须长期保存的数据。

MissAV 的唯一权威主体库、字段、两种 CSV 来源、目录过滤和合并规则见 `curated-library.md`。

## 历史语义

- `historical` 表示规范番号已存在于 `missav-library.csv`；它不同于本次输入内部重复。
- 只有用户明确选择保留的结果才能进入主体库。
- 同一番号再次出现时可以作为本次结果展示，但默认从“新增”输出中排除。
- `loveav_in_raindrop` 与 `loveav_in_skill_added` 表示来源事实，不是两套历史库。
- 未确认的可疑番号保持 `review`，不能污染正式查重键。
- 同一番号的不同 URL、标题、目录和 Tags 必须保留为字段补全或来源变体，不能因主键合并而丢失。

## 禁止持久化

不得把以下内容写入主体库、结果 CSV、日志、备份或 GitHub：

- Telegram 消息正文；
- OTP、密码、API hash、Bot Token、Cookie、浏览器存储或 Session；
- 浏览器登录数据；
- 用户未选择保留的普通候选；
- 模型临时推断且尚未确认的永久规则。

## 写入与恢复

任何主体库导入或修改都必须：

1. 先只读预览新增、重复、补全、冲突、无效、范围外和待复核数量；
2. 展示冲突的关键字段差异；
3. 等待用户明确确认；
4. 在 `backups/` 创建当前主体库备份；
5. 写入临时文件并完成 CSV 结构、唯一键和行数校验；
6. 原子替换主体库；
7. 失败时保留旧库并报告失败，不留下半写文件。

恢复备份同样先预览、校验并再次备份当前库。删除主体库行属于破坏性操作，必须明确确认。

## 导入与迁移

支持三种只读输入：

- Raindrop 官方 11 列 CSV；
- MissAV 浏览器脚本 14 列结果 CSV；
- v0.5.13 SQLite 迁移器生成的候选 CSV。

v0.5.13 旧库始终只读打开。可以提取状态明确的番号、可信 URL、女优/类型 Tags 和非敏感 Raindrop 元数据；不得迁移 Session、凭据、已读位置、Bot offset、Telegram 原文、缓存、网络任务状态或 123AV 账号状态。

旧库提取结果只是导入候选，仍需经过规范番号、范围、重复和冲突预览后才能写入唯一主体库。迁移过程不得修改现有规则数据。

## 数据同步

本地文件是正式真源。用户可以使用 Google Drive 桌面同步工具同步私人数据目录，但必须避免两个设备同时编辑同一个主体库：

- 合并前检查文件修改时间和 SHA-256；
- 发现双端变化时保留两份，生成冲突预览；
- 不使用“最后写入者自动覆盖”；
- GitHub 不保存私人 CSV、备份或运行数据。

## UI 边界

只有批量主体库编辑、冲突复核、备份恢复或旧版迁移适合使用小型 UI。日常处理、查重、列表输出和脚本生成仍由 Skill 的自然语言工作流完成。
