# 本地数据、精选库与管理契约

## 永久数据

本地主机只能持久化用户明确选择保留的派生业务数据，例如：

- 来源身份与工具绑定；
- 确定性消息身份与内容哈希；
- 规范化结果行及其来源链路；
- 永久精选库记录及其历史键；
- 参考标签、两层黑名单、不可变规则版本和差异记录；
- 待确认规则建议，以及带正负回归样本的用户确认规则；
- 可选的精简运行/输出元数据和错误分类，但不得保存完整输入记录；
- 仅作为本地导出产物保存的 Raindrop 映射，不得包含 API 凭据或远程会话。

禁止把 Telegram 消息正文、OTP、密码、API hash、Bot Token、cookie、浏览器存储或 Session 文本持久化到这些表或文件中。

只有用户选择入库的记录才构成产品的持久知识库。某条处理结果如果用户没有选择保留，即使它曾出现在预览里，也必须保持临时状态。

## 历史语义

- 同一消息/工具组合再次出现时必须保持幂等，但仍可作为本次运行结果展示。
- 消息被编辑时，应更新原有来源链路并重新处理受影响工具。
- 消息被删除时，应创建墓碑记录或失活记录，不能静默抹掉审计历史。
- 手动文本工具只有在用户选择某条派生结果后才保存；保存后才能参与未来查重与参考判断。
- `historical` 表示规范键已存在于精选库；它不同于“本次输入内部重复”。

## 精选库文件

权威精选记录保存在本地 CSV 或等价本地表中，至少包含：

```text
tool
canonical_key
primary_value
secondary_value
tags
folder
first_seen_at
last_seen_at
seen_count
rule_version
status
```

可以从权威精选库生成更小的 `history-index.csv` 用于快速查重，但禁止把生成索引当成唯一真源直接编辑。

参考标签与两个 MissAV 黑名单必须保持独立文件。标签黑名单不得删除精选结果；精选库记录也不得静默变成黑名单规则。任何自动建议都先进入预览，只有用户明确晋级后才生效。

更新必须使用临时文件配合原子替换，保留带时间戳的备份，并验证表头、唯一键、UTF-8 和行完整性。规则建议只有在明确确认和回归检查后才能激活。

即使 CSV 被其他 AI 工具打开，本地主机仍负责文件锁与冲突检测。

## 数据操作

所有查询、新建、更新、批量更新、删除、恢复、复制与导出操作，都必须通过带表白名单和字段校验的宿主适配器执行。

大数据量查询使用游标分页。跨页选择应保存筛选条件和排除项，而不是无限增长的 ID 列表。

破坏性或高影响写入必须满足：

1. 先展示预览、影响数量以及冲突/无效明细；
2. 取得操作专用确认令牌或用户明确确认；
3. 创建操作前快照；
4. 使用一个事务，任一错误则回滚；
5. 写入审计记录，但不得包含原始正文或敏感信息。

UI 可以提供业务视图和高级表格视图，但不得开放任意 SQL。长文本应使用合适编辑器，不要通过反复单字段追问完成大规模编辑。

## 数据包与迁移

结果包、资料库包、规则包与备份包必须包含清单和 SHA-256。

导入一律先预览以下数量：

- 新增；
- 重复；
- 冲突；
- 无效；
- 跳过。

确认前不得写入；冲突不得静默覆盖。

v0.5.13 迁移在确认前必须只读：先检查来源完整性、schema 和哈希，预览映射，创建目标快照，再在一个事务中提交业务记录。

可以迁移：番号、标签、任务历史、可靠来源绑定、Raindrop 导出映射。

不得迁移：Session、凭据、已读位置、Bot offset、原始 Telegram 正文、缓存、网络任务内部状态、123AV 账号状态。

## 仅适合 UI 的操作

以下场景可以使用小型 UI：

- 批量标签或黑名单编辑；
- 来源绑定修正；
- 大量冲突复核；
- 数据库备份或恢复；
- 旧版迁移。

UI 只是本契约的适配器，不得形成第二套产品逻辑。
