# MissAV 对话式操作面板

本文件把没有图形界面的 MissAV 工作流组织成简短、可继续的对话。目标是保留 TG Exporter GUI 中有意义的“来源、范围、查重、输出、已读”选择，同时不要求用户一次写完复杂提示词。

## 何时启动

用户只说“使用 LoveAV 的 MissAV”“开始 MissAV 工作”“处理番号”等，但没有给齐输入来源和范围时，启动本向导。`MSSAV`、`MS SAV` 等明显口误也按 MissAV 理解。

如果用户已经提供群组、消息链接/ID、时间范围、文件和所需输出，就直接复述关键参数并开始，不重复询问已经明确的选项。任何一步都接受自然语言，不要求用户只能回复编号。

宿主支持原生选择卡片、按钮或单选/多选控件时优先使用；不支持时使用下面的编号文本。两种界面必须表达相同选项，不能因为宿主不同而改变默认规则。

## 第一步：选择输入来源

首次回复只询问来源，不同时堆叠所有后续问题：

```text
已进入 MissAV 工作。先选择消息来源：
1. 日常未读：检查四个固定来源（推荐）
2. 番号待提取：由你提供消息位置或范围
3. 上传文件或粘贴文本
4. 组合多个来源

回复编号即可，也可以直接发消息链接、文件或描述范围。
```

选择“日常未读”时，若 TG Exporter 已连接，应在下一步显示四个固定来源的实时未读数，并允许“全选”或选择部分来源。不能把缓存数量冒充实时数量；无法读取时显示“未读数暂不可用”。来源标题与稳定匹配规则见 `missav-telegram-sources.md`。

选择“组合多个来源”时，先列出五个 Telegram 来源和“上传/粘贴”选项。默认勾选四个固定未读来源，不默认勾选 `番号待提取`，因为它还需要用户提供范围。

## 第二步：选择消息范围

四个固定来源默认且只使用“当前未读快照”，不再追问日期或数量。每群独立冻结边界。

只有选择 `番号待提取` 时才询问：

```text
请选择“番号待提取”的范围：
1. 从一条消息链接或 ID 开始，到当前最新（推荐）
2. 两个消息 ID 之间
3. 指定日期范围
4. 最近 N 条

请直接发送对应的链接、ID、日期或数量。
```

起点默认包含；两个 ID 默认两端都包含；日期范围必须明确时区和结束边界；最近 N 条必须按用户给出的总数自动分页，不能误把单页 500 当成总上限。

上传文件或粘贴文本不询问 Telegram 范围；若输入包含多来源且无法稳定识别，才列出来源让用户绑定。

## 第三步：选择处理方案

来源和范围明确后，只提供三个有实际差异的处理方案：

```text
请选择处理方案：
1. 标准处理：提取并去重，排除主体库已有番号，生成完整浏览器脚本（推荐）
2. 全量重查：提取并去重，不排除主体库已有番号，生成完整浏览器脚本
3. 只预览：先返回新增、历史、重复、无效和可疑项，不生成脚本
```

“标准处理”是默认项。用户说“默认”“照常处理”“直接开始”时使用标准处理。无论哪种方案，陌生格式都进入自适应复核，不能因不符合旧正则而静默丢弃。

## 输出与已读默认值

标准处理和全量重查默认输出：

- 输入及逐来源统计；
- 新增/全量的纯番号列表；
- MissAV 链接列表；
- 一个合并的完整浏览器脚本；
- 网页脚本操作说明。

脚本仍遵守 `missav-browser-script.md`：正式主体库派生参考女优 Tag、两层黑名单和三目录结果。除非用户主动选择“分别生成”，多个来源默认合并为一个脚本。

四个固定未读来源默认采用“成功处理后标已读”；`番号待提取`、上传文件和粘贴文本默认不改变 Telegram 已读状态。执行前用一行明确展示这一默认值，用户可以说“本次不标已读”覆盖。当前工具不支持机器可读标记已读时，仍完成处理并报告能力缺口。

## 执行摘要

选项齐全后，返回一份紧凑摘要并立即执行，不再增加没有意义的确认步骤：

```text
本次设置
- 来源：四个固定群组的当前未读
- 处理：排除主体库已有番号
- 输出：番号、链接、合并浏览器脚本
- 已读：成功来源确认到各自冻结上界

开始读取并处理。
```

如果本轮包含尚未得到明确授权的外部写操作，必须在该动作发生前单独取得确认；已经保存在私人配置中的固定四群已读策略可以作为用户持久选择，但仍要在执行摘要中可见。

## 进度与结束报告

处理过程中按阶段报告，不逐条刷屏：来源发现、未读快照、读取完成、提取/查重完成、脚本校验、逐群已读结果。网络读取时间与本地过滤时间分开报告。

结束时必须逐来源列出：

- 冻结消息范围和输入数；
- 有效候选、重复、主体库已有、新番号、可疑项；
- 是否完整处理；
- 是否标记已读以及确认到哪个冻结上界；
- 快照后是否仍有新消息。

若一个来源失败，不能把整批声称为完全成功，也不能标记该失败来源；成功来源可以继续形成合并脚本和独立完成已读确认。

## 快捷说法

以下说法等价于直接选择预设，无需再启动完整向导：

```text
用 LoveAV 按默认设置处理 MissAV 日常未读。
```

表示：四个固定来源当前未读、排除正式主体库已有番号、生成一个合并脚本、成功来源按冻结上界标已读。

```text
用 LoveAV 处理番号待提取，从这条消息到最新：<消息链接>
```

表示：只处理手动范围来源、包含起点、排除主体库已有番号、生成脚本、不自动标已读。
