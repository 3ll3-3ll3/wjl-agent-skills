# MissAV Telegram 来源规则

本文件定义 MissAV 直接读取 Telegram 时的固定来源与未读处理语义。稳定 `chat_id` 只保存在用户的私人 `LoveAV-Data/config/telegram-sources.json`，不得提交 GitHub；仓库只记录可读标题和行为规则。

## 来源分组

### 手动范围来源

- `番号待提取`

该来源不参加常规未读扫描。用户每次提供消息链接、消息 ID、起止日期或其他明确边界后，才读取并处理指定范围。若只提供起点，则读取该消息（含）到执行时最新消息。读取本身不改变已读状态，除非用户当次另有明确要求。

### 固定未读来源

- `【番号帝】番号查询`
- `Whos.tv`：必须匹配频道，不得误用同名或近似名的讨论群。
- `AV|高清无码|个人收藏`
- `AV收藏|优质精选|无码破解|中文字幕|番号磁力大全`
- `磁力后花园`

用户调用 LoveAV 的 MissAV Telegram 工作流时，应同时检查这五个来源。每个来源只处理该次开始时冻结的未读快照；零未读来源直接跳过。不能仅按标题首项匹配，必须使用私人配置中的稳定 `chat_id` 校验来源。

## 一次运行的处理顺序

1. 对五个固定来源分别读取当前未读下界与最新消息上界，冻结为本轮范围。
2. 完整读取各自 `lower < message_id <= upper` 的消息；不同来源独立分页，任何来源分页失败都标记为该来源失败。
3. 按 MissAV 规则提取、规范化和去重番号，并与正式 `missav-library.csv` 查重。
4. 合并五个来源的新番号，保留每个番号的来源关系和每个群组的输入、无效、重复、历史、新增数量。
5. 使用正式模板生成并校验一个合并浏览器脚本。若合并后没有新番号，也要输出“本轮无新番号”的成功报告。
6. 只有某个来源的未读快照已完整读取且其内容已成功完成上述处理，才可把该来源标记已读到冻结的 `upper`。不得标到执行过程中后来到达的新消息。
7. 任一来源读取不完整、过滤异常或脚本生成/校验失败时，不标记该来源已读；其他已独立成功的来源可以分别完成确认。
8. 标记已读的结果必须逐群报告：原未读数、处理范围、确认到的消息 ID，以及是否仍有快照后新消息。

网页端 MissAV 脚本的实际运行不属于 Telegram 已读确认门槛。已读表示 Telegram 消息已被 LoveAV 完整提取并形成经过校验的处理结果，不表示对应 MissAV 页面查询一定成功。

## 能力边界

当前正式 `tgctl` 可以发现来源、读取消息和报告未读数量，但尚无命令行标已读接口。若宿主没有“按冻结上界确认已读”的受支持操作，LoveAV 必须完成读取、过滤和脚本生成，然后明确报告“结果已生成，标记已读尚未执行”；不得伪称已读。

TG Exporter GUI 已有“当前未读 → 导出后标已读”，但它的确认点是 JSON 导出成功，而不是 LoveAV 脚本生成成功。需要全自动执行上述顺序时，应先在 TG Exporter 中增加受确认保护、按冻结上界执行的机器可读标记已读操作。
